# 能力评估保存反馈优化

用户已确认：保留批量保存与版本历史，区分加入草稿和正式提交，并增加未保存离开提醒。

## 实现范围

- 弹窗按钮“加入待保存修改”；主操作“保存全部修改”，未保存栏保持可见。
- 仅服务器成功响应后显示已保存数量和版本；提交失败保留草稿。
- 侧栏切页、退出登录、视图切换、页面刷新、浏览器关闭/刷新与应用路由离开提醒。
- 保存中禁止编辑/重复提交/应用内离开；浏览器关闭仍由浏览器原生提示决定。
- 不在 localStorage 持久保存敏感能力草稿；主动确认放弃后不保留草稿。
- 无数据库结构、权限、历史数据修改；不在生产环境写入测试分数。

为支持浏览器前进/后退的 SPA 导航阻止，根路由改用 React Router 已提供的
createBrowserRouter/RouterProvider；保留现有 Routes、URL 与页面映射。
跨页面草稿提示由一个专用于能力编辑的 Context 协调，不重构业务路由。

## 边界及使用说明

修改能力后，先点“加入待保存修改”，最后必须点“保存全部修改”，直到看到绿色成功提示和版本号。
点击“放弃修改”或在离开提醒中明确确认离开，将丢弃未提交内容。
浏览器刷新/关闭提示使用浏览器原生机制，提示文字和是否显示由浏览器控制；不保证浏览器崩溃、进程强制结束时恢复草稿。

本次沿用现有批量版本与服务端权限机制，没有改动 API 路径、保存请求内容、数据库表、员工分数或历史记录。
测试证明前端交互与保护逻辑，不代表已在 Jetson 上验证真实账户重新登录。后续部署结果如下。
