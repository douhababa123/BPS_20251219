# 能力画像 GAP 排名矩阵设计

## 背景

能力画像当前支持：

- 在个人视图中逐个选择工程师，查看其 9 个模块的 GAP 汇总；
- 在团队排名视图中查看各模块所有工程师的 GAP 总分。

当前缺少一张能同时比较“所有工程师 × 所有能力模块”的表格。此外，个人模块总 GAP 目前通过“平均 GAP × 技能记录数”反推，在存在未完成评估时可能被放大。

## 目标

- 在能力画像的“排名 Ranking”中显示工程师 GAP 排名矩阵。
- 每行显示一名工程师在 9 个模块中的 GAP 总分。
- 每行显示该工程师跨模块的个人总 GAP，并据此默认降序排名。
- 表格底部显示每个模块所有工程师的 GAP 总分及全团队总 GAP。
- 统一个人、模块和团队汇总的 GAP 计算口径。

## 非目标

- 不新增独立导航或页面。
- 不修改数据库结构或后端 API。
- 不改变能力评估数据的录入方式。
- 不在本次增加部门筛选、分页或多年度趋势分析。

## 计算口径

有效评估记录必须同时满足 `current_level > 0` 和 `target_level > 0`。

- 单项 GAP：使用评估记录的 `gap`，其业务含义为 `target_level - current_level`。
- 个人模块总 GAP：指定年度、指定工程师、指定模块下所有有效评估记录 GAP 的直接求和。
- 个人总 GAP：该工程师 9 个模块总 GAP 的求和。
- 团队模块总 GAP：指定年度内所有工程师在该模块总 GAP 的求和。
- 全团队总 GAP：所有工程师个人总 GAP的求和，且必须等于 9 个团队模块总 GAP 的求和。

负 GAP 保留原值，不截断为 0，以确保汇总忠实反映 `Target - Current`。没有任何有效评估记录的工程师/模块交叉单元格显示 `—`；存在有效记录且合计为零时显示 `0.0`。

## 页面设计

矩阵放置在能力画像的团队视图 →“排名 Ranking”中，位于现有模块排名表之前。现有模块排名表继续保留。

矩阵列为：

1. 排名
2. 工程师
3. 9 个能力模块（按固定模块顺序）
4. 个人总 GAP

矩阵行规则：

- 默认按个人总 GAP 降序；同分时按工程师姓名稳定升序。
- 排名前三名沿用现有排名视觉标识。
- 模块名称较长时使用紧凑表头，并通过 `title` 提供完整名称。
- 表格允许横向滚动，固定工程师识别列和个人总 GAP 列，保证宽屏和窄屏可用。
- 底部“模块合计”行显示每个模块所有人的 GAP 总分；最右显示全团队总 GAP。

当前年度选择器继续作为唯一时间范围来源。切换年度后矩阵、个人排名和模块合计同步更新。

## 代码结构

在 `src/lib/competencyAggregation.ts` 新增纯聚合函数和明确的数据类型。聚合函数接收当前年度的评估记录与技能定义，输出：

- 工程师排名行；
- 固定顺序的 9 个模块列；
- 各模块团队合计；
- 全团队合计。

`src/pages/Competency.tsx` 只负责调用聚合函数和渲染矩阵，不重复实现求和逻辑。个人模块汇总改为直接使用聚合阶段保存的 `totalGap`，不再通过平均值反推。

## 异常与空状态

- 当前年度没有评估数据时，显示明确空状态，不渲染空排名。
- 找不到技能对应模块的评估记录不计入矩阵，避免归入错误模块。
- 未完成评估不参与 GAP 求和，但可使对应单元格保持 `—`。
- 聚合函数不抛出 UI 级异常；数据请求失败继续沿用页面现有错误处理。

## 测试与验收

为纯聚合逻辑补充单元测试，至少覆盖：

- 多名工程师、多个模块的交叉汇总；
- 个人总 GAP 降序和同分姓名排序；
- 团队模块合计与个人合计交叉校验；
- 未填写 Current/Target 的记录不参与计算；
- 有效零 GAP 显示为零，完全无数据与零值可区分；
- 负 GAP 保留；
- 个人模块总 GAP 直接求和，修复缺失记录下的反推偏差。

发布前运行前端单元测试、TypeScript 检查和构建。推送 `DEV` 后由现有 `Jetson CI/CD Pipeline` 自动部署；以 GitHub Actions 的测试、部署任务成功及 Jetson `/api/health` 健康检查通过作为发布完成条件。

## 发布与回滚

本变更不涉及数据迁移。发布通过提交并推送 `DEV` 触发现有 GitHub Actions。若部署或页面验证失败，回滚该功能提交并再次推送 `DEV`，由同一工作流恢复上一版本。
