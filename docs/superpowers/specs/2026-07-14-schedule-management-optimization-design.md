# 日程管理优化设计

## 背景

日程管理页面当前使用饼图展示能力域工时，任务录入对话框仍包含旧地点 `GPU-SU`，任务状态采用必填按钮组，Leave 任务没有专用表单规则，跨天连续任务的日历卡片工时含义也不够清晰。本次优化覆盖团队视图、个人视图、任务录入对话框和日历任务卡片，但不改变现有 API 或数据库结构。

## 目标

1. 将团队与个人视图的“能力域工时分布”改为柱状图，并按工时从高到低排列。
2. 将任务录入地点选项 `GPU-SU` 替换为 `Supplier`，同时兼容编辑含旧值的历史任务。
3. 将任务状态改为非必填下拉选择，空值提交时使用 `planned`。
4. 为 Leave 任务提供自动填充和字段锁定规则。
5. 跨天连续任务在每个日历格中显示该任务的完整连续总工时。

## 设计决策

### 1. 能力域工时柱状图

团队视图和个人视图复用同一套能力域聚合与排序规则。聚合后按 `value` 降序排列；工时相同时按能力域名称排序，确保显示稳定。图表使用 Recharts `BarChart`，每根柱子沿用当前能力域配置颜色，Tooltip 继续显示小时数。

### 2. Location 选项迁移

任务录入的标准地点列表使用 `Supplier` 替代 `GPU-SU`。新建任务不再提供 `GPU-SU`。编辑历史任务时，如果当前值为 `GPU-SU`，下拉框临时保留该值，用户可主动改为 `Supplier`，避免浏览器因缺少 option 而丢失旧数据。

Leave 使用专用地点值 `out of office`。该值只在 Leave 模式下自动选择并显示。

### 3. 可选任务状态

现有四按钮状态选择改为单个下拉框，选项为：

- 计划中 `planned`
- 进行中 `in_progress`
- 已完成 `completed`
- 已取消 `cancelled`

下拉框包含“请选择...”空选项，不显示必填星号，也不使用 HTML `required`。提交时空值规范化为 `planned`，从而保持后端兼容性。

### 4. Leave 表单规则

当任务类型切换为 `Leave` 时：

- `task_name` 自动设置为 `Leave`。
- `task_location` 自动设置为 `out of office`。
- 清空能力域、Competence Item、分配工程师、任务状态和备注。
- 除任务类型、开始日期、结束日期、时间槽以外的输入全部禁用。
- 禁用字段不参与必填校验。

从 Leave 切回其他任务类型时，清空自动生成的任务名称和地点，并恢复所有普通字段的编辑能力。编辑既有 Leave 任务时，在弹窗首次渲染后直接进入相同的锁定状态。

### 5. 连续任务工时显示

日历按天重复渲染覆盖当天的任务卡片。任务跨越多个日期时，前端根据起止日期（含首尾日期）和 `hours_per_day` 计算连续时段工时，并显示 `max(total_hours, 连续天数 × hours_per_day)`。这样即使历史或导入数据把跨天任务的 `total_hours` 保存成单日 8 小时，每个日历格仍会显示完整连续时段的最大工时。例如 3 个全天连续日的任务显示 `24h`，而不是 `8h`。

单日全天任务继续显示 `8h`；半天任务按对应 `hours_per_day` 计算。日期无效或缺失时回退到现有 `total_hours`。Tooltip 和紧凑任务卡使用同一个连续工时显示值；数据库原值不被修改。

## 代码边界

- `src/lib/scheduleRules.ts`：新增纯函数，负责能力域统计排序、地点选项兼容、Leave 表单转换和工时显示值。
- `src/lib/__tests__/scheduleRules.test.ts`：覆盖所有规则的单元测试。
- `src/pages/Schedule.tsx`：接入规则函数，替换图表和表单控件。
- `src/components/TaskCard.tsx`：使用统一工时显示规则。
- `src/components/__tests__/TaskCard.test.tsx`：覆盖连续任务卡片显示。
- `src/lib/taskTypeConfig.ts` 与相关类型：更新标准地点列表。

## 验证

1. 单元测试验证能力域降序、稳定排序、Location 迁移、状态默认值和 Leave 字段转换。
2. 组件测试验证跨天任务每个紧凑卡显示完整总工时。
3. TypeScript 类型检查和生产构建必须通过。
4. 页面验收同时覆盖团队/个人能力域图表、新增普通任务、新增 Leave 任务、编辑历史地点和跨天任务卡片。
5. 推送 `DEV` 后，GitHub Actions 的代码质量与 Jetson 部署 Job 必须成功。

## 非目标

- 不迁移或批量改写数据库中已有的 `GPU-SU` 记录。
- 不新增任务状态或修改后端状态枚举。
- 不修改日历的日期范围、工作日计算或现有权限流程。
- 不改变总工时在数据库中的计算公式。
