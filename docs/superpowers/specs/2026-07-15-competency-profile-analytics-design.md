# 能力画像分析优化设计

## 背景

能力画像团队视图当前包含“差距分析、排名、总分视图”三个子页。差距分析与总分视图重复显示 9 大模块雷达图，差距分布同时展示总 GAP 和平均 GAP；独立排名页保存了有价值的工程师 × 模块 GAP 汇总，但排名语义已不再需要。页面还缺少人员分配和季度趋势，个人视图继续显示了不需要的模块平均 GAP。

本次优化覆盖原需求 4.1–4.7，并同步把能力等级上限从 5 统一收紧为 4。当前数据库共有 38 个启用技能、430 条当前评估记录，且不存在现状或目标为 5 的记录，因此无需清理数据。

## 目标

- 取消独立 Ranking 入口和排名语义，同时保留工程师/模块 GAP 汇总能力。
- 总分视图使用 9 大模块平均现状与平均目标，固定为 0–4，并在图形上直接显示数值。
- 差距分析只展示 GAP 总数，增加人员分配柱状图和季度末总 GAP 趋势。
- 个人视图不再展示模块平均 GAP。
- 能力评估的前端输入、后端校验和数据库约束统一限制为 0–4。

## 非目标

- 不恢复或重命名任何排名功能。
- 不增加多条模块趋势线；趋势图始终显示筛选范围的一条总 GAP 线。
- 不提供员工、部门或离职时间的历史组织快照。
- 不修改当前评估“当前表 + 追加历史表”的数据模型。
- 不增加新的能力模块或技能定义。

## 已确认的页面结构

### 团队视图

团队视图只保留“差距分析 Gap Analysis”和“总分视图 Total Score”。

差距分析按以下顺序显示全宽卡片：

1. **差距分布**：模块级/技能级切换；只显示 GAP 总数。
2. **人员 GAP 分配**：模块/技能切换、单项筛选、一人一柱，按 GAP 降序；零值人员保留。
3. **季度总 GAP 趋势**：当前选择年度的 Q1–Q4、一条总 GAP 线、模块与技能联动筛选。
4. **工程师模块 GAP 汇总**：由原排名矩阵迁移而来，删除名次并按工程师姓名排序，保留个人模块 GAP、个人总 GAP、模块团队总 GAP和团队总 GAP。

原模块排名表不再保留，因为差距分布已经表达 9 个模块的总 GAP。

### 总分视图

现有总目标、总实际、总差距 KPI 和总分明细表保持不变。雷达图与柱状图改为：

- 每个模块的平均现状与平均目标；
- 坐标范围固定为 0–4；
- 平均值显示一位小数；
- 柱状图在柱顶显示标签；
- 雷达图在现状和目标顶点附近分别显示标签，使用不同颜色和偏移避免重叠；
- Tooltip 保留完整模块名和精确值。

### 个人视图

- 模块级差距柱状图显示模块总 GAP，不显示模块平均 GAP。
- 模块能力汇总表删除“平均 GAP”列。
- 技能级视图继续显示单项技能 GAP。

## 统计口径

### 当前数据

- 有效能力等级为 0–4；0 是有效评估值并参与平均分分母。
- 平均分范围为当前所选年度、当前在职工程师和当前启用技能。
- 缺失记录不参与平均，并与真实 0 分区分。
- 模块平均现状 = 模块内有效现状之和 ÷ 有效记录数。
- 模块平均目标 = 模块内有效目标之和 ÷ 有效记录数。
- 单项 GAP = 目标 − 现状。
- 所有总 GAP 均直接累加单项 GAP，不通过平均值反推。
- 平均分固定显示一位小数；GAP 总数按实际精度显示。

当前数据库没有 5 分记录。实现不采用“将 5 截断为 4”的兼容算法，而是在录入边界阻止 5。

### 季度末快照

季度趋势表示季度末完整团队状态，而不是该季度发生的修改次数。对每个季度末、当前在职工程师和当前启用技能：

1. 从全部历史中查找该工程师/技能在季度末之前的最后一条有效记录。
2. 当季度没有修改时沿用以前季度的最后记录。
3. Q1 可以沿用上一年度最后记录。
4. 将筛选范围内快照的 GAP 直接求和。

选择年度后固定返回 Q1–Q4。没有任何历史基线的季度返回 `totalGap: 0` 与 `hasData: false`；真实零 GAP 返回 `totalGap: 0` 与 `hasData: true`，Tooltip 据此区分“暂无历史基线”和“总 GAP 为 0”。

## 人员分配交互

人员分配采用已确认的方案 A：

- 维度为“模块”时列出 9 个模块；维度为“技能”时从接口数据动态列出当前 38 个启用技能。
- 默认选中第一项可用能力。
- 横轴显示当前在职工程师，纵轴显示所选能力的个人总 GAP。
- 默认按 GAP 降序，同分按姓名稳定升序。
- 零值人员仍显示；完全没有当前评估记录的人员以 0 显示并在 Tooltip 标注“暂无评估”。

## 趋势筛选器

- 模块默认“全部模块”。
- 技能默认“全部技能”。
- 选择模块后，技能选项只保留该模块的启用技能。
- 当前技能不属于新模块时自动重置为“全部技能”。
- 非法模块/技能组合由后端返回 HTTP 422。

## 架构与数据流

采用前后端分工方案：

- 当前年度模块平均分、差距分布、人员分配和汇总矩阵继续在前端由纯聚合函数生成。
- 后端新增季度趋势聚合接口，在 SQL Server 中选择季度末版本并完成筛选汇总，只返回季度合计，不返回员工历史明细。
- 前端通过独立 API 客户端与 React Query hook 获取趋势数据。

建议接口：

`GET /api/competency-assessments/gap-trend?year=2026&module_id=7&skill_id=123`

返回：

```json
{
  "year": 2026,
  "moduleId": 7,
  "skillId": 123,
  "quarters": [
    { "quarter": 1, "label": "2026 Q1", "totalGap": 12, "hasData": true },
    { "quarter": 2, "label": "2026 Q2", "totalGap": 10, "hasData": true },
    { "quarter": 3, "label": "2026 Q3", "totalGap": 0, "hasData": false },
    { "quarter": 4, "label": "2026 Q4", "totalGap": 0, "hasData": false }
  ]
}
```

趋势接口对所有已认证且可访问能力画像的用户返回团队汇总，不暴露人员级历史。历史明细接口的管理员/本人权限保持不变。

## 代码边界

为避免继续扩大 `src/pages/Competency.tsx`，只进行与本需求相关的拆分：

- `TeamGapAnalysis`：团队差距图、人员分配、趋势和汇总矩阵。
- `TotalScoreView`：平均分图表、现有 KPI 和明细。
- `PersonalGapAnalysis`：个人图表、汇总和建议。
- `competencyAggregation.ts`：当前数据的纯聚合函数。
- 趋势 API 客户端与 hook：服务端状态和筛选参数。

## 能力评估上限

- 编辑对话框的现状和目标只提供整数 0–4。
- 前端验证规则为 `0 ≤ 现状 ≤ 目标 ≤ 4`。
- 后端保存模型和保存接口执行相同校验，越界返回 HTTP 422。
- 数据库当前表与历史表约束从 0–5 收紧为 0–4。
- 迁移执行前校验不存在 5；若发现越界数据则停止迁移，不自动截断。

## 异常与空状态

- 当前评估请求失败时沿用页面整体错误与重试。
- 趋势请求失败时只在趋势卡片显示错误和重试，不影响其他图表。
- 没有人员或能力数据时显示明确空状态。
- 数据标签空间不足时保留 Tooltip；窄屏图表区域允许横向滚动。

## 测试与验收

- 聚合单元测试覆盖 0 分参与平均、模块平均、总 GAP、人员排序和姓名排序矩阵。
- 后端测试覆盖 0–4 校验、5 被拒绝、季度末最新版本、跨季度/跨年度沿用、模块/技能筛选、无基线标记和非法组合。
- 组件测试覆盖 Ranking 入口移除、平均 GAP 移除、动态技能数量和筛选器重置。
- 运行前端 Vitest、TypeScript、生产构建和后端 pytest。
- 推送 DEV 后通过现有 GitHub Actions 部署 Jetson，检查 Actions、`/api/health`、能力评估 0–4 和能力画像图表/筛选/数据标签。

## 发布与回滚

发布顺序为数据库约束迁移、后端、前端。迁移前验证无 5 分记录并保留恢复点。若验证失败，不修改数据库。应用回滚可恢复上一版代码；数据库约束回滚仅通过经过验证的回滚 SQL 恢复到 0–5，历史数据不删除。
