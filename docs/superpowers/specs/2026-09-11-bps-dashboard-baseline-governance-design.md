## 4. 能力评估页面设计

### 4.1 权限模型

| 角色 | 查看 | 编辑 |
|---|---|---|
| 管理员 | 全部人员、全部模块 | 全部人员、全部模块 |
| 模块 Owner | 全部人员、全部模块 | 仅自己负责模块内的全部人员 |
| 普通用户 | 全部人员、全部模块 | 无编辑权限，包括不能修改本人 |

当某人同时是管理员和模块 Owner 时，管理员权限优先。

页面中的可编辑状态只是提示；每次保存必须由后端根据 JWT 用户、员工状态、账号状态、模块和 Owner 配置重新授权。

### 4.2 草稿与统一保存

- 用户修改单元格后，先形成页面草稿。
- 未点击“保存”时，不写入最新评估表和历史表。
- 页面显示未保存修改数量，并提供“保存”和“放弃修改”。
- 保存请求只提交发生变化的单元格，但这些单元格必须在一个数据库事务中全部成功或全部失败。
- 每个单元格仍校验 `0 <= 现状 <= 目标 <= 4`；缺失现状或目标不能保存。
- 保存成功后，同时更新 `dbo.competency_assessments` 最新投影，并向历史表追加记录；不得覆盖旧历史。

为了把一次页面保存识别为一个业务版本，新增版本头信息，建议表名为 `dbo.competency_assessment_versions`，记录：

- 版本 ID
- 保存人
- 保存时间
- 修改单元格数量
- 来源，例如 `WEB_BATCH_SAVE`
- 可选说明

历史表增加可空的 `version_id`。已有历史行保持原值，`version_id` 为空，不进行数据重写。

每条新保存的历史明细还必须记录并可查询：

- 修改时间：使用服务端统一保存时间，同一批次共用同一时间和版本 ID。
- 修改人员：保存认证用户 ID，并关联显示用户姓名和邮箱。
- 修改内容：明确保存修改前、修改后的现状 Level 和目标 Level；新建单元格的修改前值为空。

能力评估页面向有编辑权限的人员提供“修改记录”入口。管理员可查看全部模块；模块 Owner 只能查看自己负责模块；普通用户不显示该入口，后端也拒绝越权读取。已有历史不回填、不改写；因旧记录没有显式保存前值，页面显示为历史原值不可用。

### 4.3 并发保护

- 页面加载时获得当前版本标识。
- 保存时提交该标识。
- 如果其他人已先保存相关单元格，后端返回冲突，不覆盖对方数据。
- 前端重新加载最新值，并保留用户草稿供人工比较。

本次不实现自动合并冲突。

## 5. 年度基线设计

### 5.1 基线是独立、不可变的业务快照

新增两类数据：

- `competency_annual_baselines`：年度基线头，包含年度、来源、版本/导入批次、选定人和选定时间。
- `competency_annual_baseline_items`：该基线内每个员工-技能单元的年初现状和年度目标。

基线数据与当前评估、普通历史分开保存。建立基线不会把当前能力回退，也不会修改既有历史记录。

每年只能有一个生效基线。管理员重新选择时，旧基线保留为非生效版本，不删除。

### 5.2 管理员入口与 Excel 上传

用户已确认增加管理员上传年初基线 Excel 的入口，并由网页直接识别原始宽表。以下交互以“预览不落库、确认才生效”为安全边界。

**入口：左侧“管理员” → “年初基线管理”页签。** 在现有 `src/pages/Admin.tsx` 管理员控制台中增加独立页签，不与员工、技能或当前能力评估的通用导入混用。

- 仅管理员可见并可操作；非管理员（包括仅有模块 Owner 身份的用户）直接请求相关管理接口也必须被拒绝。
- 页面提供年度选择，展示“未设置”或当前生效基线的版本、来源文件名、确认人、确认时间及覆盖人数/技能数/单元数。
- 操作包括“下载模板”“上传年初 Excel”“移除待确认文件”“查看基线版本”。后续年度的历史版本选择见 5.3。
- 年度已有生效基线时，当前状态卡提供“下载当前基线”和“修改/替换年初基线”。下载文件包含当前生效版本的完整现状/目标值，可直接编辑后重新上传；页面明确展示“下载并修改 → 上传预览 → 确认替换”的步骤。
- “修改”不是直接更新旧基线明细，而是建立新的不可变版本并将旧版本转为历史。未完成预览和确认前不写入任何业务数据。
- 上传区必须在文件选择前提示：只识别名称完全为 `Current_Target states` 的工作表，请先核对表名（包括下划线和空格）；其余工作表一律忽略。
- 总览没有基线时，管理员可通过“设置年初基线”进入该页签并带入当前所选年度；普通用户仅看到“请联系管理员设置年初基线”。

操作顺序：

1. 选择基线年度，例如 2026；年度由管理员明确选择，不根据上传日期推断。
2. 上传经业务确认的该年度年初 Excel；文件必须包含名称完全为 `Current_Target states` 的工作表。
3. 系统只读取该工作表，自动识别标准长表或已确认的原始 C/T 宽表并转换，然后展示完整预览：员工、模块、技能、来源单元格、转换规则、年初现状、年度目标、GAP，以及源员工行数、导入单元数、不适用省略数、错误数、年初 Level、目标 Level、年初 GAP 总分。明细通过分页全部可查看，不截断为前 200 行。
4. 校验全部通过后，管理员点击“确认设为 2026 年初基线”。确认提示明确说明只建立独立基线，不覆盖当前评估和历史。
5. 后端重新校验本次预览对应的同一文件内容、年度及权限，事务成功后显示生效版本，并刷新总览的对应年度 KPI/趋势。切换年度或换文件必须重新预览。

仅上传、预览、移除文件、取消或校验失败时，均不创建生效基线，不写入基线业务表，也不修改任何已有系统记录。“移除文件”同时清空浏览器文件控件、预览和校验消息。失败必须说明具体工作表、行、字段和原因，不能只显示通用 `422`，也不能部分导入成功。

#### 5.2.1 支持的上传格式与校验

标准 `.xlsx` 模板和原始宽表都使用 `Current_Target states` 工作表。标准模板采用一行一个“员工-技能”单元的明细格式：

| 字段 | 规则 |
|---|---|
| 员工 ID | 必填，引用现有员工；模板同时提供姓名供核对，不仅凭姓名模糊匹配 |
| 技能 ID | 必填，引用现有技能；模板同时提供模块名、技能名供核对 |
| 年初现状 | 必填数值，0–4；0 是有效值，空白不等于 0 |
| 年度目标 | 必填数值，0–4，且不得小于年初现状 |

- 模板可带出现有员工/技能标识和名称，但现状、目标留空，不把当前数据预填成年初数据。
- 管理入口直接接收标准长表或 5.2.1.1 描述的原始宽表。原始宽表由服务器按明确映射转换；不接受其他任意布局，也不读取其他工作表。
- 找不到精确工作表名时阻止预览，并同时显示要求的名称和文件中实际检测到的工作表名称。
- 无法解析、缺必需列、空文件、无有效明细、非数值、超范围、目标小于现状、员工/技能不存在、重复员工-技能行均须阻止确认，并显示行号、字段和原因。
- 完全空白行可忽略；已填写员工/技能的行不得因现状或目标为空而静默跳过。没有提供的单元不自动补 0，也不强制构造全部员工 × 全部技能的评估。
- 不自动新建员工或技能，不修改员工、模块 Owner、技能或账号资料。

#### 5.2.2 生效、替换与可追溯性

- 2026 年只从已确认的年初 Excel 建立基线；2026-07-03 迁移快照不是可用替代来源。
- 确认后保存基线头和不可变明细，记录年度、来源 `EXCEL_IMPORT`、文件名、确认人、确认时间和版本标识。上传时间不冒充年初评估时间。
- 同年已有生效基线时，提示“替换将重新计算该年度 KPI 和趋势”，必须明确确认替换。取消时保留原基线不变。
- 替换仅新增基线版本并调整基线生效标记；旧基线头和明细保留可追溯，不覆盖或删除。并发确认时检测生效版本变化，拒绝过期确认并要求重新核对，保证每年只有一个生效版本。
- 年初 Excel 不通过普通能力导入接口写回 `competency_assessments`，也不追加或改写 `competency_assessment_history`；账号、密码、任务及其他业务记录全部保持原样。
- 导入不会生成虚构的月度修改记录；历史月份仍按 6.3 的真实历史及沿用规则计算。

### 5.3 2027 年及以后

- 同一管理入口支持按年度上传经确认的年初 Excel，校验和生效规则沿用 5.2。
- 管理员也可从已保存的能力评估业务版本中选择一版。
- 系统按该版本保存时刻重建完整快照，并复制为对应年度的不可变基线明细。
- 普通用户和模块 Owner 不能设置年度基线。

### 5.4 固定比较范围

一个年度的 KPI 使用该年度基线中存在的员工-技能单元作为固定比较范围：

- Level 0 参与平均值计算。
- 不在基线中的缺失单元不进入分母，也不按 0 处理。
- 年中新增员工或新增技能默认从下一年度基线开始进入 KPI。
- 员工后来停用时，年度历史 KPI 仍保留其基线单元，避免趋势因人员范围变化而失真。
- Tyler Tan 与 Tong Zhifeng 不写入年度基线，因此其能力记录可用于资源匹配，但不参与 Competence development 的 Level、GAP、关闭率及趋势计算。

### 6.1 页面替换

### 6.1.1 年度、统计月份与模块联动

补充独立的“统计月份”选择器，页面顶部顺序为“年度 → 统计月份 → 能力模块”。以下默认值和交互已纳入应用层实现：

- 首次进入默认当前年度、当前月份、全部模块。
- 当前年度只允许选择 1 月至本月；未来月份禁用，不能把未来值显示为 0 或预测值。
- 切换到历史年度时默认 12 月，可选择 1–12 月；切回当前年度时默认本月。未来年度如出现在年度列表中，仅展示“尚未开始”，不生成进度值。
- 选择已结束月份时，统计截止点为该月月末；选择本月时，截止点为本次查询时间，并标注“截至当前，非月末数据”。日期边界统一按 `Asia/Shanghai` 计算。
- 年度、月份、模块共同决定查询范围。切换模块保持所选年度和月份；切换月份保持所选年度和模块。
- 改变月份只改变当前/YTD 三项指标及趋势截止月；同一年度和模块下的年初 Level、目标 Level、年初 GAP 保持不变。
- 页面显示“统计范围：2026 年 06 月｜全部模块｜截至 2026-06-30”等范围说明；当月显示实际查询截止时间。

### 6.2 六项 KPI

设年度基线单元集合为 `B`。对每个基线单元 `i`：

- `C0(i)`：基线年初现状。
- `T0(i)`：基线年度目标。
- `Ct(i)`：所选统计月份截止点之前最新保存的现状；没有后续修改时沿用 `C0(i)`，不得将所选月份之后的修改带入历史月份。

计算规则：

1. 年初 Level = `AVG(C0(i))`
2. 目标 Level = `AVG(T0(i))`
3. 当前 Level = `AVG(Ct(i))`
4. 年初 GAP 总分 = `SUM(T0(i) - C0(i))`
5. 当前 GAP 总分 = `SUM(MAX(T0(i) - Ct(i), 0))`
6. GAP 关闭率 = `(年初 GAP 总分 - 当前 GAP 总分) / 年初 GAP 总分`

补充规则：

- 所有 Level 保留 1 位小数，图表最大值为 4。
- GAP 显示整数总分。
- 关闭率显示百分比。
- 年初 GAP 为 0 时关闭率显示 `—`，不得除以 0。
- 当前 GAP 始终对比年度基线目标 `T0`，避免年中修改目标后改变年度进度口径。

### 6.2.1 六项 KPI 布局与动态标题

桌面宽屏在筛选器下方横向一排展示六项等宽 KPI，标题在上、数值在下，数值基线对齐。顺序固定如下，以选择 2026 年 6 月为例：

| 顺序 | 标题示例 | 数值来源 |
|---:|---|---|
| 1 | 2026 年初 Level | 年初现状平均值 |
| 2 | 2026 目标 Level | 年初基线目标平均值 |
| 3 | 现状 Level（2026 YTD06） | 截至所选月份的现状平均值 |
| 4 | 2026 年初 GAP 总分 | 年初目标与现状差值总和 |
| 5 | GAP YTD06 | 截至所选月份的 GAP 总分 |
| 6 | GAP 关闭率（2026 YTD06） | 截至所选月份的关闭率 |

- `YYYY` 来自所选年度，`MM` 来自所选统计月份且补齐两位；选择 6 月显示 `YTD06`，不是一律显示系统当前月份。第 5 项通过公共统计范围说明标识所属年度。
- 宽屏（视口宽度不小于 1280px）六项同排；较窄屏幕可按三列、两列或一列顺序折行，避免标题和数值被截断，不强制挤成六列。
- Level 保留 1 位小数，GAP 保持整数，关闭率以未提前舍入的总分计算后显示百分比，最多保留 1 位小数，例如 `20%`、`20.5%`。
- 无生效基线时保留六项标题，数值显示 `—`，统一提示“未设置年度基线”，不能显示为六项 0；所选模块没有基线单元时显示“该模块无基线数据”。

### 6.3 月度组合趋势图

同一张双轴组合图显示：

- 柱状图：每个月末 GAP 总分。
- 折线图：每个月末 YTD GAP 关闭率。
- 左轴：GAP 总分。
- 右轴：关闭率百分比。
- 横轴：`YYYYMM`。

趋势图按自然月连续展示所选年度 1 月至所选统计月份，不只列出发生过修改的月份，也不展示所选截止月之后的数据点。历史月份使用该月最后一刻之前的最新已保存值；当月没有保存时沿用上月值。当前月份使用当前最新已保存值。未来月份不绘制数值。

年度、统计月份和模块筛选必须同时作用于六项 KPI 与趋势图。

### 6.3.1 KPI 与同月图表的一致性

- 六项 KPI 和趋势序列由同一次后端响应返回，使用同一年度、模块、基线版本、统计范围和截止时间，不允许分别请求后混用不同版本的数据。
- “GAP YTDMM”必须等于趋势最后一个月份柱子的原始 GAP 数值；“GAP 关闭率（YYYY YTDMM）”必须等于该月折线点。图表提示框与 KPI 使用相同舍入规则。
- 后端返回所选年度/月、模块、基线 ID、统计截止时间和统计单元数；当前 GAP/关闭率直接复用所选月的趋势计算结果，避免两套算法。
- 筛选切换期间同时显示加载状态；不得将新月份标题与旧月份数值组合展示。只接受与当前筛选匹配的响应，过期响应不得覆盖新结果；请求失败时显示错误而非伪装成最新数据。
- 年初 GAP 为 0 时，关闭率 KPI 显示 `—`，对应折线数据为不可用值并断开，不绘制虚假的 `0%` 点，提示框说明“年初 GAP 为 0，关闭率不适用”。
- 验收例：年初 GAP 为 200、6 月 GAP 为 160，选择 2026 年 6 月时，KPI 显示 `GAP YTD06 = 160`、关闭率 `20%`；6 月柱子和折线提示框必须分别为 `160` 和 `20%`，不能沿用示意图中的 `150`、`25%`。

### 6.4 无基线和数据质量状态

- 选择的年度没有生效基线时，KPI 显示“未设置年度基线”，不回退到迁移快照。
- 导入时无法匹配员工或技能的项目必须阻止整批确认，不能静默丢弃后生效。若已生效基线后续发生引用完整性异常，应显示数据质量告警，不得静默缩小固定分母或展示为完整 KPI。
- API 返回参与统计的基线单元数，方便核对分母。

## 8. 智能任务匹配设计

### 8.1 候选资格硬条件

候选人必须同时满足：

1. 员工和账号启用。
2. 每个必需能力项都有评估记录。
3. 每个能力项满足 `target_level = required_level` 或 `current_level >= required_level`。
4. Lead/Expert 等现有角色门槛继续满足。

只有通过全部硬条件的人员进入候选排序；缺失评估不能按 Level 0 后继续参与推荐。时间冲突不再是资格硬门槛，而是绝对第一排序维度。

Tyler Tan（员工编号 `SCh_Tyler_Tan`）和 Tong Zhifeng（员工编号 `15001437`）是资源匹配专用人员。两人仍须满足员工/账号启用、所需能力评估、上述能力资格和角色门槛，但匹配时不查询日程，并按 100% 时间可用参与排序。此例外仅适用于智能资源匹配，不删除、不修改也不依赖两人的日程记录。当前数据库中两人均为启用员工但能力评估数为 0；在录入其匹配用能力前，他们可以出现在“建议人选”下拉框，但不会进入有能力要求的合格候选列表。

### 8.2 排序和显示

- 时间符合度是绝对第一排序条件，不再与能力得分计算加权综合分。普通员工存在部分日程冲突时不直接淘汰，而是按任务工作日内可用工时除以任务要求工时计算 `0%–100%` 的时间符合度；如果所有人员时间都不完全匹配，仍返回候选人并优先显示时间符合度最高者。
- 只有时间符合度完全相同时才比较能力：目标 Level 与需求 Level 一致优先，其次是当前 Level 与需求 Level 一致，最后是当前 Level 超过需求；超过需求时差值越小越优先，避免高等级资源浪费。
- 多项能力使用关键项权重 2、普通项权重 1，依次比较目标精确匹配率、当前精确匹配率和当前能力超配差值。
- 候选能力资格调整为：每项要求必须有评估，并且满足 `target_level = required_level` 或 `current_level >= required_level`。因此允许“当前 L2、目标 L3、需求 L3”的发展型匹配；“当前 L2、目标 L4、需求 L3”不进入推荐。
- 建议人只作为上述业务条件全部同分后的优先项，不能绕过启用状态、评估存在性、能力资格或角色门槛。
- API 返回全部合格候选人，前端可默认显示前 5 名并提供展开，避免合格人员因服务端截断而无法核对。
- 最终仍同分时按员工姓名稳定排序。

### 8.3 Huang Lanping 场景

数据库当前显示 Huang Lanping 的 `Logistic index` 为 `3/3`，但 2026-09-15 至 2026-09-21 存在全天任务冲突。因此验收时必须使用完全相同的日期、角色、模块和能力要求，只改变要求 Level：

- 如果要求 L3，能力属于目标/当前精准匹配；即使时间有部分冲突也保留候选资格，但必须按照实际时间符合度排序并展示冲突。
- 如果要求 L2，能力属于当前能力超配；相同时间符合度下排在精准匹配候选人之后。
- 如果要求 L4，则因为 `target 3 != required 4` 且 `current 3 < required 4`，不得成为候选人。

## 9. API 边界建议

- `GET /api/competency-assessments/matrix`：返回每个单元格的模块级编辑权限和当前版本标识。
- `POST /api/competency-assessments/batch-save`：原子保存草稿并生成业务版本。
- `GET /api/competency-assessment-versions`：管理员查看可选择的历史版本。
- `GET /api/competency-annual-baselines?year=YYYY`：管理员查看该年度基线状态、明细和版本来源。
- `GET /api/competency-annual-baselines/template`：管理员下载年初 Excel 模板。
- `POST /api/competency-annual-baselines/import-preview`：管理员上传所选年度 Excel，只解析、校验并返回预览，不写入业务表。
- `POST /api/competency-annual-baselines`：管理员明确确认后从已预览的同一文件内容或允许的历史版本建立年度基线；校验年度、生效版本并发标识和替换确认。
- `GET /api/dashboard/competency-progress?year=YYYY&month=MM&module_id=N&employee_id=UUID`：一次返回六项 KPI、1 月至所选月的月度序列、筛选回显、基线 ID、统计截止时间、统计单元数和数据质量告警。全部模块或全部人员时分别省略 `module_id`、`employee_id`；月份校验为 1–12 且不得查询尚未到来的进度。
- `GET /api/dashboard/competency-progress/employees?year=YYYY`：返回该年度生效基线涉及的人员选项；无生效基线时返回空列表。

最终路由名称可按现有 FastAPI 风格微调，但必须保持权限、事务和统计口径。

## 10. 数据保护与迁移原则

- 所有数据库变更必须先备份并在事务中执行。
- 迁移仅新增表、索引和可空关联字段，不更新或删除现有评估、历史和任务值。
- 任何自动把 `MIGRATION_BASELINE` 标记为年度基线的脚本都属于禁止项。
- 基线导入必须先预览，再由管理员确认。
- 失败时回滚新事务；已有业务记录保持不变。
