# 日历半天任务位置设计

## 背景

日程管理的团队日历当前使用相同宽度显示上午、下午和全天任务，主要依赖图标区分时间槽。用户无法仅通过任务条的位置快速判断任务发生在上午还是下午。本次调整只改变日历任务条的布局，不修改任务数据、工时规则、连续任务识别或日历格外观。

## 目标

1. 上午任务靠近日期格左半部分，下午任务靠近右半部分，使时间段一眼可辨。
2. 全天任务继续占据完整日期格宽度。
3. 不在页面上显示明显的上午/下午分隔格，保持当前日历视觉风格。
4. 保留连续任务的连接、固定高度、稳定轨道和仅首段显示文字等现有规则。

## 布局设计

每个日期格内部使用两个等宽的隐形定位列：左列代表上午，右列代表下午。定位列仅用于 CSS 布局，不渲染分隔线、独立边框、背景色、“上午/下午”标题或其他可见网格元素。

- `AM`：任务条占左侧 50% 宽度。
- `PM`：任务条占右侧 50% 宽度。
- `FULL_DAY`：任务条横跨左右两列，占 100% 宽度。

日期单元格本身继续沿用现有背景、边框和内边距。用户看到的变化只有半天任务条靠左或靠右，不会看到日期格被明显切成两个小格。

## 同日多个任务

- 同一天同时存在上午和下午任务时，两者可在同一水平轨道左右并排显示。
- 同一半天存在多个任务时，在对应半格内上下排列，不继续横向切分。
- 全天任务独占一个完整宽度的轨道；其他半天任务排列在其下方。
- 任务排序保持稳定，避免刷新后任务条位置跳动。

半格宽度不足以同时显示任务名称和辅助信息，因此普通的 `AM`/`PM` 半天任务条采用名称优先的精简模式：可见区域只渲染任务名称，不再渲染任务类型首字母、状态图标、时间槽图标和工时。左右位置已经表达上午/下午，任务条颜色继续表达能力域；任务卡片的 `title`/悬停信息仍提供完整任务名称、类型、状态、时间槽和工时。

`FULL_DAY` 全天任务以及跨日期连续任务不使用精简模式，继续保留现有任务类型、状态和累计工时显示。任务名称超过半格可用宽度时使用省略显示。

## 连续任务

现有连续任务识别算法保持不变，只根据每个片段的时间槽调整宽度与水平位置：

- 全天任务连接到次日上午时，第一天占满日期格，次日上午片段占次日左半格。
- 当日下午连接到次日上午时，第一天片段占右半格并延伸至日期边界，次日上午片段从次日左边界开始。
- 时间槽之间存在空档时继续拆分显示，不创建视觉连接。
- 超过一天的连续任务只在最左侧首段显示一次任务名称和连续总工时，中段与尾段不重复文字。
- 所有连接片段继续保持统一的 26px 高度和同一水平轨道。

连续任务的布局只影响显示，不合并或修改数据库记录。

## 代码边界

- `src/lib/scheduleRules.ts`：生成任务的日期格布局元数据，包括时间槽对应的列位置和稳定轨道排序。
- `src/pages/Schedule.tsx`：将日期格任务容器改为隐形双列布局，并在已分配与未分配任务行中复用相同规则。
- `src/components/TaskCard.tsx`：根据时间槽与连续片段元数据应用半宽、满宽和连接边缘样式。
- 相关规则与组件测试覆盖定位、排列和连续任务兼容性。

## 验收标准

1. 单独的上午任务显示在日期格左半部分。
2. 单独的下午任务显示在日期格右半部分，左侧保留空白。
3. 全天任务占满日期格可用宽度。
4. 同日一个上午任务和一个下午任务在同一轨道左右并排。
5. 同一半天多个任务在对应半格上下排列。
6. 页面不出现新的半格分隔线、背景块或时间标题。
7. 跨天连续任务保持正确连接、同高、同轨道，并且只在最左段显示文字。
8. 普通上午/下午任务条至少显示任务名称，不被类型、状态、时间槽或工时图标完全挤占；完整信息可通过悬停查看。
9. 全天与跨天连续任务保持原有详细显示。
10. Firefox 视觉检查、单元测试、组件测试、类型检查和生产构建通过。
11. 推送 `DEV` 后，GitHub Actions 的代码质量和 Jetson 部署作业成功。

## 非目标

- 不按 3.5h/4.5h 比例将日期格切分为 43.75%/56.25%；上午和下午固定使用等宽半格。
- 不增加小时刻度或具体开始/结束时间。
- 不改变任务录入对话框中的时间槽选项。
- 不修改后端 API、数据库结构或工时计算方式。
