# 日历任务上下排列与完整名称设计

## 背景

日程管理月历需要让用户快速区分上午和下午任务，同时完整阅读任务名称。左右半格方案虽然能表达时间位置，但每个任务条只有日期格的一半宽度，任务名称容易被类型、状态、图标和工时挤压甚至完全不可见。

本次调整改为纵向时间顺序：上午任务在日期格上方，下午任务在下方，二者均使用日期格完整宽度。普通任务名称完整换行；跨天连续任务只在第一天显示完整名称，后续日期使用同高的无文字片段连接。

## 已确认的视觉方案

1. 每个日期列的最小宽度由 80px 调整为 100px。
2. 普通 `AM` 和 `PM` 任务均占日期格完整可用宽度，不再左右并排。
3. 同一天的任务按全天/跨天、上午、下午的顺序由上到下排列。
4. 普通任务名称自动换行并完整显示，任务条及工程师行随内容增高。
5. 跨天连续任务的完整名称只在第一天单元格内自动换行。
6. 后续跨天片段不重复文字，高度同步第一段，并与相邻片段无缝连接。
7. 日期格内部不增加可见的上午/下午分隔线、独立背景块或子格标题。

## 日期格与任务排序

日期表头和正文单元格统一使用 `min-width: 100px`，月历继续通过现有横向滚动容器浏览整月。

每个日期格使用单列纵向任务容器，显示顺序为：

1. `FULL_DAY` 全天任务和跨天连续任务；
2. `AM` 上午任务；
3. `PM` 下午任务。

同一时间槽存在多个任务时，在对应分组内继续向下堆叠。排序使用稳定的任务 ID、连续任务组 ID 和现有任务排序字段，避免刷新后任务顺序跳动。

## 普通任务显示

普通任务卡取消固定 26px 高度和单行 `truncate`：

- 任务名称占据完整内容宽度，使用正常换行和长单词断行，必须完整显示；
- 名称下方使用较小的辅助信息行显示状态、上午/下午或全天、工时；
- 类型和能力域继续通过任务条颜色、辅助信息及悬停内容表达；
- 卡片高度由名称和辅助信息自然撑开；
- 工程师所在表格行由该行各日期格中最高的内容自然撑开。

任务点击、悬停详情、双击日期空白新增任务等交互保持不变。

## 跨天连续任务

跨天任务继续由各日期单元格内的片段组成，不改为覆盖整行的单一绝对定位元素，以保留现有表格点击、滚动和任务碰撞逻辑。

### 第一段

- 第一段位于任务开始日期的单元格；
- 名称只能使用第一天单元格的可用宽度，不借用后续日期宽度；
- 名称完整自动换行；
- 名称下方显示连续总工时和状态；
- 第一段仅保留左侧圆角，右侧边缘连接下一日期。

### 中段和尾段

- 中段和尾段不显示名称、状态或工时；
- 中段取消左右圆角和相邻边框；
- 尾段仅保留右侧圆角；
- 片段跨过单元格内边距连接，相邻日期之间不得出现可见空隙。

### 高度同步

第一段在名称完成换行后测量实际高度。该高度以连续任务 `groupId` 为键，保存在当前工程师日历行的共享高度表中，并应用到同组的所有中段和尾段。

- 首次渲染使用布局阶段测量，避免用户看到明显的高度跳动；
- 使用 `ResizeObserver` 监听列宽、字体和窗口尺寸变化，变化后重新测量；
- 后续片段始终使用第一段的最新高度；
- 若测量暂时不可用，使用 26px 作为安全的初始最小高度，并在测量完成后同步；
- 任务名称只在第一段显示一次，但整条任务任意片段仍可点击打开同一任务详情。

## 组件与代码边界

- `src/lib/scheduleRules.ts`
  - 将日期格布局从左右列改为单列纵向排序；
  - 保持连续任务识别、组 ID、隐藏重复记录和稳定排序规则；
  - 输出全天/跨天、上午、下午的显示顺序元数据。
- `src/components/TaskCard.tsx`
  - 支持普通任务名称完整换行和辅助信息第二行；
  - 支持跨天第一段内容与无文字中段/尾段；
  - 接收并应用连续任务同步高度。
- `src/components/CalendarDayTasks.tsx`
  - 使用单列纵向容器渲染日期任务；
  - 报告第一段实际高度，并给其他连续片段应用共享高度；
  - 保持任务点击和悬停信息。
- `src/pages/Schedule.tsx`
  - 将日期列最小宽度调整为 100px；
  - 通过工程师行级组件维护连续任务组高度，供该行所有日期共享；
  - 已分配和未分配任务行复用相同渲染规则。

## 数据与业务规则

本次变更仅调整日历显示，不修改：

- 后端 API 和数据库结构；
- 上午 3.5h、下午 4.5h、全天 8h 的时间槽规则；
- 连续任务的四项身份识别条件；
- 连续总工时计算；
- 任务状态、审批或分配流程。

## 测试与验证

自动化测试覆盖：

1. 日期列最小宽度为 100px；
2. 全天/跨天、上午、下午按纵向顺序排列；
3. 上午和下午任务均占完整日期宽度；
4. 普通任务名称取消截断并完整换行；
5. 同一时段多个任务继续纵向堆叠；
6. 跨天任务仅第一段显示名称和总工时；
7. 中段和尾段不重复文字且边缘无缝连接；
8. 第一段高度变化后，同组所有片段同步到相同高度；
9. 窗口或列宽变化后重新测量；
10. 点击、悬停和双击空白新增任务行为不回归。

完成自动化测试、TypeScript、针对性 ESLint、生产构建和 OpenSpec 严格校验后，使用 Firefox 对真实 2026 年 7 月任务进行视觉检查，再通过 GitHub Actions 部署到 Jetson 并复验。

## 验收标准

1. 每个日期列最小宽度为 100px。
2. 上午任务显示在下午任务上方，二者均占日期格完整宽度。
3. 普通任务名称完整显示，必要时自动换行并增加任务条及工程师行高度。
4. 全天任务使用完整日期宽度并保留完整名称。
5. 跨天任务名称只在第一天单元格内完整换行显示。
6. 后续跨天片段与第一段等高、无重复文字、无可见间隙。
7. 跨天任务所有片段保持稳定轨道，并可打开同一任务详情。
8. 页面没有新增可见的上午/下午子格或分隔线。
9. 自动化检查和 Firefox 视觉检查通过。
10. GitHub Actions 的代码质量检查与 Jetson 部署作业成功，部署页面复验通过。

## 非目标

- 不按 3.5h/4.5h 比例划分单元格高度；上午和下午高度由实际任务内容决定。
- 不增加小时刻度、具体开始/结束时间轴或拖拽调整时长。
- 不合并或重写跨天任务的数据库记录。
- 不修改任务录入对话框中的时间槽选项。
- 不修改后端、数据库或工时计算方式。
