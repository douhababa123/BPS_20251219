# GitHub Actions 与 Jetson 部署详解

## 🤔 核心概念解释

### 什么是 GitHub Actions？

**简单理解**: GitHub Actions 就是 GitHub 提供的**免费"机器人"服务**，可以帮你自动执行重复性工作。

**类比**: 
- 就像你雇了一个助手，每次你提交代码，助手就自动帮你：
  1. 检查代码有没有错误
  2. 打包你的应用
  3. 远程登录到你的 Jetson
  4. 自动更新部署

---

### 什么是 GitHub Secrets？

**简单理解**: 存储敏感信息（如密码、密钥）的**加密保险箱**。

**为什么需要**:
- ❌ **不能**直接把 Jetson 的密码写在代码里（所有人都能看到）
- ✅ **要**放在 GitHub Secrets（只有你和 GitHub Actions 能访问）

## 🎯 为什么需要 CI/CD？（针对后续功能迭代）

### 场景对比

#### ❌ 没有 CI/CD（传统方式）

**每次更新功能你需要做的事**:

```bash
# 在 Windows 上
1. 写代码
2. 手动测试（npm run typecheck）
3. 提交到 Git
4. git push

# 然后 SSH 到 Jetson
5. ssh user@10.70.80.183
6. cd ~/BPS_20251219
7. git pull
8. docker-compose down
9. docker-compose build  # 等待 5-10 分钟
10. docker-compose up -d
11. 手动测试是否正常
12. 如果有问题，再手动回滚

总耗时: 20-30 分钟
错误风险: 高（可能忘记某个步骤）
```

#### ✅ 有 CI/CD（自动化）

**每次更新功能你需要做的事**:

```bash
# 只在 Windows 上
1. 写代码
2. git add .
3. git commit -m "feat: 新功能"
4. git push origin DEV

# 完成！GitHub Actions 自动完成剩余所有步骤
# 你可以去喝咖啡，5-10 分钟后收到部署成功通知

总耗时: 2 分钟（你的操作） + 5-10 分钟（自动执行）
错误风险: 极低（自动化流程，失败自动回滚）
```

## 🔑 GitHub Secrets 详解

### 为什么需要 Secrets？

**场景**: GitHub Actions 需要 SSH 到你的 Jetson 部署代码

**错误做法** ❌:
```yaml
# .github/workflows/jetson-deploy.yml
- name: SSH 到 Jetson
  run: |
    ssh root@10.70.80.183  # 密码是: MyPassword123
```
**问题**: 
- 你的 GitHub 仓库是公开的 → 所有人都能看到密码
- 所有人都能 SSH 进你的 Jetson！

**正确做法** ✅:
```yaml
# .github/workflows/jetson-deploy.yml
- name: SSH 到 Jetson
  run: |
    ssh ${{ secrets.JETSON_USER }}@${{ secrets.JETSON_HOST }}
    # 使用 secrets.JETSON_SSH_KEY 认证
```
**优势**:
- 密码存储在 GitHub Secrets（加密）
- 只有你和 GitHub Actions 能访问
- 代码可以安全地公开

### Secrets 配置步骤

```
1. 打开 GitHub 仓库
   https://github.com/douhababa123/BPS_20251219

2. 点击 Settings → Secrets and variables → Actions

3. 点击 "New repository secret" 添加 3 个 Secret:

   Secret 名称              |  值                        | 说明
   ─────────────────────────┼───────────────────────────┼──────────────
   JETSON_HOST              |  10.70.80.183              | Jetson IP 地址
   JETSON_USER              |  你的用户名                 | SSH 用户名
   JETSON_SSH_KEY           |  -----BEGIN RSA KEY-----   | SSH 私钥
                            |  MIIEpAIBAAKCAQEA...       | (完整内容)
                            |  -----END RSA KEY-----     |

4. 保存后，GitHub Actions 就能使用这些信息连接你的 Jetson
```

## 🤔 常见疑问

### Q1: GitHub Actions 会一直运行吗？会不会很贵？

**A**: 
- GitHub Actions 是**按需运行**的（只在你 push 代码时运行）
- 公开仓库**完全免费**（每月 2000 分钟）
- 私有仓库也有每月 2000 分钟免费额度
- 你每次部署大约用 10 分钟，一个月 200 次部署都不会超

### Q2: GitHub Actions 服务器在哪里？会不会很慢？

**A**:
- GitHub 的服务器在全球各地（包括亚洲）
- 但它只是执行测试和构建，然后 SSH 到你的 Jetson
- 实际部署是在你的 Jetson 本地执行，速度很快

### Q3: 如果 GitHub Actions 失败了怎么办？

**A**:
- 如果测试失败 → 不会部署，你的 Jetson 保持原样
- 如果部署失败 → 自动回滚到上一版本
- 你可以在 Jetson 上手动部署: `bash update.sh`

### Q4: 我可以不用 GitHub Actions，只用手动部署吗？

**A**: 
- 可以！所有脚本都支持手动执行
- `bash deploy.sh` - 首次部署
- `bash update.sh` - 更新部署
- GitHub Actions 只是**可选的自动化工具**

### Q5: 如果我的代码仓库是私有的，还能用吗？

**A**:
- 可以！GitHub Actions 对私有仓库也免费提供 2000 分钟/月
- 配置方式完全一样
